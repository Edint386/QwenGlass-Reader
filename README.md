# QwenGlass-Reader 文字版：在千问 AI 眼镜上看自己的 TXT 小说

![两个版本的功能演示：滑动翻页、菜单、章节跳转、自动翻页、字号、粗细、亮度、行距、语音指令、智能翻页、听书、段落标记](docs/demo.gif)

<sub>一张图里是两个版本的功能：没有标签的两个版本都有，标了「页图版」「文字版」的只有那个版本有。在本地模拟器里录的，模拟器和千问开放平台的页面预览用同一个渲染内核，书是自带的原创示例。每格右上角的绿标是这一下做的手势，下面一行是说的话和眼镜的回答。调设置的几格从打开设置面板开始。模拟器的计时比真机慢，自动翻页那一格按真机的节奏加快了。</sub>

这个仓库有两个分支，是同一个阅读器的两种接入方式。现在看的是 `agent`（文字版），页图版在 [`main`](https://github.com/Edint386/QwenGlass-Reader) 分支。两个版本可以各跑一个实例，挂同一个书库和进度目录，换个 Skill 接着读。

## 两个版本能做什么

| | 页图版（`main`） | 文字版（`agent`，本分支） |
|---|---|---|
| 平台上怎么接入 | MCP 插件 + Skill | Agent 自定义接入（WebSocket） |
| 平台要不要开通 | 不用 | 账号要先开通「自定义接入」白名单 |
| 正文怎么显示 | 服务把每页画成图片 | 眼镜的原生文字 |
| 滑动翻页 | ✅ 约 1 秒一页，每页要下载一张图 | ✅ 立即响应 |
| 菜单 | ✅ | ✅ |
| 章节跳转 | ✅ 菜单里滑动选章，面板上显示章名；也能语音说第几章 | ✅ 菜单里滑动选章，面板上显示第几章；也能语音说第几章 |
| 自动翻页 | ✅ 每页停 1～30 秒 | ✅ 每页停 1～30 秒 |
| 智能翻页：按这一页的字数算停多久 | ❌ | ✅ 每秒 4～60 字 |
| 听书 | ❌ | ✅ 平台朗读，页面跟着翻 |
| 语音指令 | ✅ 经过大模型，说法随意，要等几秒 | ✅ 不经过大模型，只认固定说法，立即执行 |
| 字号 | ✅ 16～32，九档 | ✅ 16～32，七档 |
| 粗细 | ✅ 六档 | ✅ 常规、粗体 |
| 行距 | ✅ 五档 | ❌ 固定 |
| 亮度（页面遮罩） | ✅ 10%～100% | ✅ 10%～100% |
| 真机亮度（眼镜本身） | ❌ | ✅ 0～100，平台下发了调亮度的工具才能用 |
| 段落标记 | ❌ | ✅ 圆点、竖线、下划线、圆角框 |
| 缺字 | 不缺：服务用自己的字体画 | 眼镜字体里没有的字显示成空白 |
| 阅读进度 | 存在服务上，两个版本共用 | 同左 |

## 怎么工作

平台的「Agent 自定义接入」用 WebSocket 连到你的服务。服务读 TXT、分章，按眼镜原生字体的字宽排好版，把正文当文字发给眼镜。页面里有 8 页文字排成一圈，翻页只是换显示哪一页，所以立即响应；服务一边记进度，一边把前后的页补上，网络卡一下也还能往后翻 4 页、往前翻 3 页。

不接大模型，语音只认固定说法。

| 路径 | 内容 |
|---|---|
| `glassreader/` | 服务的 Python 源码。文字版在 `agent.py`，字宽表在 `native_font.py`；断行和打开书借用页图版的 `pager.py`、`mcp_tools.py`，所以页图版的代码也在 |
| `skill/Pages/reader-text/` | 眼镜页面 `template.xml` 和 Mock 数据 `data.json` |
| `deploy/` | `Dockerfile`、`compose.yaml` 和反向代理配置示例 `site.conf` |
| `docs/demo.gif` | 上面的演示图 |

代码注释里提到的 `docs/research.md`、`docs/agent.md` 是开发笔记，没有放进这个仓库。

## 部署指南

要准备三样东西：

- 一台公网服务器和一个 HTTPS 域名。平台要从公网连进来，`wss://` 要有正规证书（Let's Encrypt 就行）。
- 一个[千问开放平台](https://device.qianwen.com)账号。第一次登录会自动注册，按提示做个人实名认证。
- 一副千问 AI 眼镜 S1，固件按官方文档的要求升级。自定义接入不支持其他型号的眼镜。

### 第一步：配置

复制 `.env.example` 为 `.env` 填好。优先级：命令行 > 环境变量 > 默认值。

| 变量 | 说明 |
|---|---|
| `READER_TOKEN` | 平台 Agent 插件的 Bearer Token，WebSocket `/agent` 用它鉴权。不填每次启动随机生成，平台插件会失效 |
| `READER_KEY` | 图片地址里的随机段（书名图）：眼镜发不了请求头，只能靠路径鉴权。只用字母、数字、`-` 和 `_` |
| `READER_PUBLIC_URL` | 眼镜和平台访问的公网根地址，如 `https://reader.example.com`，可以带路径前缀 |
| `READER_BOOKS_DIR` | TXT 书库目录，递归收集 `*.txt`，扩展名不分大小写（默认 `~/Books`） |
| `READER_STATE_FILE` | 进度文件（默认 `~/Library/Application Support/glassreader/progress.json`） |
| `READER_HOST` / `READER_PORT` | 监听地址（默认 `127.0.0.1:8780`） |
| `READER_SWAP_SWIPE` | `1` = 前滑、后滑方向对调，真机方向和预期相反时用 |

TXT 支持 UTF-8 和 GBK/GB18030，章节标题自动识别（“第 N 章”“序章”“Chapter 12”这类）。

### 第二步：部署到服务器

1. 在仓库根目录复制 `.env.example` 为 `.env`，填 `READER_TOKEN`、`READER_KEY`（各一串随机字符），`READER_PUBLIC_URL` 填你的域名。
2. 准备书库和进度目录。容器里的用户是 10001，进度目录要它能写：

   ```bash
   cd deploy && mkdir -p books data && sudo chown 10001:10001 data
   ```

3. 把 TXT 放进 `deploy/books/`，启动：

   ```bash
   docker compose up -d --build
   ```

   服务只监听本机的 `127.0.0.1:19517`，根文件系统只读，内存上限 256 MB。
4. 反向代理照 `deploy/site.conf` 配：80 端口只放行证书校验，443 只转发 `/healthz`、`/r/`（书名图）、`/agent`（平台连进来的 WebSocket，要转发 `Upgrade`），其余 404。示例里证书和日志的路径是 1Panel OpenResty 的写法，按你的服务器改。
5. 打开 `https://你的域名/healthz`，返回 `ok` 就通了。

和页图版一起用时，两个容器挂同一个 `books/` 和 `data/`，进度共用。两边写进度前都先加文件锁，所以这个目录要在同一台机器的本地磁盘上。

### 第三步：在千问开放平台上配置

文字版在平台上是一个 Agent 插件，加上平台为它自动生成的同名 Skill。仓库里的文件这样放：

| 仓库里的文件 | 放到平台上的哪里 | 怎么放 |
|---|---|---|
| 无 | Agent 插件 | 在网页上填表，见下面第 2 步 |
| `skill/Pages/reader-text/template.xml` | 关联 Skill 的 `Pages/reader-text/template.xml` | 新建页面 `reader-text`，整篇复制粘贴，保存 |
| `skill/Pages/reader-text/data.json` | 同一个页面的 Mock 数据 | 复制粘贴，只用来预览 |
| 无 | 关联 Skill 的 `SKILL.md`、`tool_schema.json` | 平台按插件的名称和描述自动生成，不用改 |

**1. 开通自定义接入**

Agent 自定义接入还是内测功能，账号要先开通白名单。打开「资源库 → Agent 插件 → 导入 Agent 插件」，「Agent 平台」下拉里有「自定义接入」就是开通了；没有的话，按官方文档里的联系方式找平台开通。

通信方式用「ASR文本」，不用再单独开通，「音频流」「音视频流」才要另外开。

**2. 新建 Agent 插件**

在「导入 Agent 插件」里填：

| 字段 | 填什么 |
|---|---|
| 插件名称 | `文字阅读器` |
| 插件描述 | 见下面。平台靠名称和描述决定你说的一句话要不要进这个插件 |
| Agent 平台 | 自定义接入 |
| WebSocket 地址 | `wss://你的域名/agent`。平台要能从公网连上，填 localhost 或内网地址保存不了 |
| 认证方式 | Bearer Token，填 `.env` 里的 `READER_TOKEN`，只填 Token 本身。认证方式一定要选，留空保存不了 |
| 通信方式 | ASR文本 |
| 连接超时 | 保持默认 |

插件描述可以这样写：

> 用千问 AI 眼镜的原生文字看 TXT 小说，镜腿翻页立即响应，支持自动翻页、字号、粗细和亮度调节。只在用户明确说“打开文字阅读器”“文字阅读器”“用文字版看小说”时使用。用户只说“看小说”“继续看小说”时不要使用，那是「眼镜看小说」技能的入口。

最后一句是为了和页图版分开，只装文字版可以删掉。填完点「创建插件」。

**3. 在关联 Skill 里加页面**

创建插件后，平台会自动生成一个同名 Skill。在插件详情页的「关联 Skill」点「编辑」进去，不要自己另建 Skill：

1. 在左侧的 `Pages` 里新建页面 `reader-text`，把 `template.xml` 粘进去，保存。
2. 把 `data.json` 粘进这个页面的 Mock 数据。右侧选「千问 AI 眼镜 S1」能预览，预览只运行已经保存的内容。
3. 页面说明写 `reader-text`。服务靠这个词找阅读页，找不到就用第一个页面。

**4. 真机测试**

1. 在「设备管理」里添加眼镜（一键绑定，或用千问 AI 穿戴 App「我的 → 扫码」），打开开发者模式。
2. 在关联 Skill 的编辑器顶部点「真机测试」，选你的眼镜。之后这副眼镜用的就是编辑中的版本，直到解绑或关掉开发者模式。
3. 对眼镜说“打开文字阅读器”。

自己用不需要发布：插件和 Skill 都是草稿时，平台也能连上服务、下发页面，我们在真机上试过（文档说页面要发布后才下发，以真机为准）。发布只影响没有绑定测试的设备。真要发布的话，范围选「个人私有」；插件发布后就锁定了，连 Token 都改不了，只能删了重建。

改了页面以后，眼镜上要退出再打开才会用上新页面。服务和页面是配套的，升级时先部署服务，再保存页面，回滚也两边一起。

### 在电脑上运行

本地跑起来主要是为了调试。需要 Python 3.12 和 [uv](https://docs.astral.sh/uv/)：

```bash
uv sync
```

```bash
uv run glassreader serve --books ~/Books --state .state/progress.json
```

不想装 uv，`pip install .` 之后直接运行 `glassreader serve` 也行。

## 眼镜上的操作

| 操作 | 阅读时 | 菜单里 |
|---|---|---|
| 前滑 / 后滑 | 下一页 / 上一页 | 移动选中项 |
| 单击 | 打开菜单 | 返回阅读、智能翻页、自动翻页、显示设置、听书、章节跳转 |
| 双击 | 底部提示“再双击一次退出”，再双击退出 | 同左 |

显示设置里能调字号（16、18、20、22、24、28、32）、粗细（常规、粗体）、亮度（遮罩，10%～100%）、真机亮度（眼镜本身，0～100）和听书时的段落标记。滑动时立即预览，单击保存。

## 语音指令

会话里麦克风一直开着，不用唤醒词。为了不误触，命令要整句说，超过 14 个字的话不当命令，别的话一律不回应。

| 想做什么 | 说法 |
|---|---|
| 翻页 | 下一页、上一页、往后翻五页、往前翻三页 |
| 换章 | 下一章、上一章、跳到第三章 |
| 跳位置 | 跳到百分之五十、跳到一半、回到开头 |
| 问 | 我看到哪了、书架上有什么书、能说什么 |
| 换书 | 打开《书名》、换一本某某 |
| 字号 | 字大一点、字小一点 |
| 亮度 | 亮度五、亮度调到五十 |
| 听书 | 开始听书、暂停、继续 |
| 智能翻页 | 智能翻页、停止智能翻页 |
| 退出 | 退出、不看了 |

亮度命令带一个数，同时定两个亮度，越大越亮：0～9 时软件亮度 10%～100%、真机亮度 0；10～100 时软件亮度 100%，真机亮度就是这个数（取整十）。

## 三种自动往下读

三种只能开一种，开一个会关掉另一个。

| | 自动翻页 | 智能翻页 | 听书 |
|---|---|---|---|
| 怎么翻 | 每页停一样久，1～30 秒 | 按这一页的字数算停多久，每秒 4～60 字 | 平台朗读，页面跟着声音翻 |
| 出声 | 不出声 | 不出声 | 朗读 |
| 位置提示 | 左栏倒计时 | 段落前的标记 | 段落前的标记 |
| 打开菜单时 | 暂停 | 暂停 | 停播，回到正文接着读 |

平台不告诉服务朗读读到哪了，所以听书按语速估（每秒约 6.6 字），段落之间留一点空隙让声音和估算对齐。摘下眼镜时听书和智能翻页都会停。
